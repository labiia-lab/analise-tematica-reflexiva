# Hierarquia Analítica na ATR

## Referência Metodológica

Este documento define operacionalmente os três níveis da hierarquia analítica na Análise Temática Reflexiva (Braun & Clarke, 2006, 2019, 2022). Use como guia durante a codificação e construção temática.

---

## Nível 1: Código

### Definição

Palavra ou frase curta que atribui um atributo sumativo, saliente e evocativo a uma porção dos dados. O código é a unidade analítica mínima.

### Critérios de um Código Adequado

Um código adequado:

**É autossuficiente**
Deve fazer sentido sem que o leitor precise ver o extrato de dados que o originou. Imagine mostrar apenas o código para alguém que não viu os dados — ele deveria entender o que está sendo capturado.

**Informa a comunalidade subjacente**
O código deve comunicar o que diferentes extratos têm em comum — não apenas descrever um extrato específico.

**Tem limites explícitos**
Deve ser possível dizer o que pertence e o que não pertence ao código. Um código sem limites é um código vago.

**Não é intercambiável**
Dois códigos distintos devem capturar coisas genuinamente distintas. Se trocar os códigos de lugar não muda a análise, um deles é redundante.

**Não depende de contexto**
O código não deve depender de conhecimento que só está disponível para quem leu o extrato completo.

### Exemplos Comentados

| Código | Adequação | Análise |
|---|---|---|
| "experiência negativa" | Inadequado | Vago demais — não informa o que especificamente é negativo |
| "participante insatisfeito" | Inadequado | Depende de contexto — o que causa insatisfação? |
| "procedimentos vistos como burocráticos e não como proteção ao paciente" | Adequado | Autossuficiente, informa a comunalidade, tem limites claros |
| "distância entre norma e prática cotidiana" | Adequado | Captura padrão de significado sem depender do extrato |
| "coisas" | Inadequado | Sem qualquer especificidade analítica |
| "restrições de tempo percebidas como barreira à implementação" | Adequado | Informativo, com limites, autossuficiente |

### O Teste do Código

Antes de registrar um código, pergunte:
1. Se eu mostrar apenas este código sem o extrato, quem me lê entenderá o que está sendo capturado?
2. Este código é diferente de todos os outros que já gerei?
3. Mais de um extrato poderia receber este código?
4. Consigo dizer o que NÃO pertence a este código?

Se a resposta a qualquer das primeiras três for não — o código precisa ser reescrito.

## Nível 2: Categoria

### Definição

Padrão emergente que agrupa códigos relacionados ou similares. A categoria representa o primeiro movimento em direção à identificação de padrões mais amplos e coloca diferentes partes dos dados em conversação.

### Função da Categoria

A categoria não é um tema — é um agrupamento intermediário que:
- Coloca códigos relacionados em diálogo
- Facilita a identificação de padrões de segunda ordem
- Serve de degrau entre o código (muito específico) e o tema (muito amplo)

### Diferença entre Categoria e Tema

| Categoria | Tema |
|---|---|
| Agrupa códigos por similaridade | Organiza significado em torno de conceito central |
| Descritiva — o que aparece junto | Interpretativa — por que aparecem juntos |
| Pode ser bastante específica | Mais abrangente e analiticamente elaborada |
| Pode conter poucos dados | Deve ter dados suficientes para suporte |

### Como Formar Categorias

Ao revisar os códigos, pergunte:
- Quais códigos capturam aspectos do mesmo fenômeno?
- Quais códigos, juntos, revelam algo que individualmente não revelam?
- O que conecta estes códigos além de aparecerem no mesmo tópico?

## Nível 3: Tema

### Definição

Padrão de significado compartilhado, organizado em torno de um conceito organizador central. O tema é a unidade analítica principal do relatório.

### O Que Faz um Tema ser um Tema

**Conceito organizador central identificável**
Todo tema tem um "porquê" do agrupamento — uma ideia que explica por que aqueles dados pertencem juntos. Este conceito deve ser nomeável e articulável em uma frase.

**Padrão de significado, não de tópico**
A diferença mais importante na ATR: temas não agrupam dados que falam sobre o mesmo assunto, mas dados que compartilham o mesmo padrão de significado.

**Contribuição analítica clara**
O tema deve dizer algo sobre a questão de pesquisa. Se um tema pode ser removido do relatório sem que a resposta à questão de pesquisa seja afetada — ele não é um tema, é um resumo de domínio.

**Construído pelo analista**
Temas não existem nos dados. O analista os constrói ao perceber padrões e criar interpretações. Isso não é fraqueza metodológica — é o trabalho da análise qualitativa.

### O Que NÃO é um Tema

**Resumo de domínio**
Dados agrupados por tópico compartilhado, não por significado compartilhado. Identifica-se pelo título: começa com "Tipos de...", "Benefícios de...", "Barreiras para...", ou é uma palavra única como "Comunicação", "Trabalho", "Família".

**Código superdimensionado**
Um código muito abrangente pode parecer um tema, mas não tem a elaboração interpretativa necessária.

**Pergunta do roteiro disfarçada**
Se o "tema" corresponde diretamente a uma pergunta do roteiro de entrevista/coleta, provavelmente é um resumo de domínio.

### Teste de Qualidade do Tema

Antes de aceitar um tema como válido, responda:

1. **Qual é o conceito organizador central?** (deve ser articulável em 1 frase)
2. **Por que estes dados pertencem juntos?** (deve ser por significado, não por tópico)
3. **O que este tema diz sobre a questão de pesquisa?** (deve ter resposta clara)
4. **Consigo definir o tema em 2-3 sentenças sem mencionar os dados?** (deve ser possível)
5. **Este tema é distintivo dos outros?** (dados internos não podem ser trocados com dados de outros temas sem perda de sentido)

## Terminologia Correta para Relatórios

| Evitar | Usar |
|---|---|
| "os dados revelaram" | "a análise identificou" |
| "temas emergiram" | "temas foram construídos/gerados" |
| "encontrei nos dados" | "construí a partir dos dados" |
| "o padrão é claro" | "o padrão foi identificado em X de Y fontes" |
| "dados mostram que" | "a análise sugere que" |
